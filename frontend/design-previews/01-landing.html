Chapter II · How a mission runs

Three movements.

i.

Dispatch

A mission lands in a lane. The watcher picks it up the moment its dependencies clear. Each agent gets its own git worktree, its own PAT, its own MCP context — no shared state, no stepping on toes.

ii.

Coordinate

Sub-missions spawn from the field. depends_on chains keep them ordered. Failed deps no longer deadlock children — terminal states release the gate cleanly.

iii.

Report

Every agent files what it did, what's open, what's untested, what's next. The report becomes the prompt for the agent that follows. The trail is durable. The handoff is honest.
